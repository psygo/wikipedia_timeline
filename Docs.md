# wiki_timeline

A vertical event timeline for Wikipedia, built as a template plus TemplateStyles
(no MediaWiki extension, no JavaScript).

## Why a template

+ EasyTimeline renders images; Chart has no timeline type.
+ `{{Timeline-start}}`, `{{Timeline-item}}`, `{{Timeline-end}}` render a plain definition list
  (docs last edited 2009).
+ Codex components need JavaScript; a timeline does not.

## Layout

+ `prototype/`: standalone HTML and CSS.
  + `index.html`: viewer. Shows `article.html` in an iframe with draggable left/right handles (also ← → keys and width presets), so the media queries react to the frame width.
  + `article.html`: mock Wikipedia article (Vector-like chrome, infobox, headings) with three example timelines: simple, several events per dot, parallel timelines, and parallel and grouped timelines.
  + `alone.html`: the timeline alone.
  + `theme-toggle.js`: prototype-only button cycling system / light / dark (sets `data-theme`, remembered in localStorage). The template itself stays JS-free.
  + `timeline.css`: the real stylesheet, written to be portable to TemplateStyles (one root class `wt-timeline`,
    Codex tokens via `var(--token, fallback)` only, no custom properties declared, no `@import`, no external urls).
  + `vector-stub.css`: fake Vector chrome and Codex tokens (light and dark); prototype only.
  + Markup is an `<ol>` of `<li>` items with a `<span>` for the date (`<time>` is not
    something I could confirm the wikitext sanitizer allows).
+ `prototype/images/huang-longshi.png`: photo of a Huang Longshi statue, supplied by the maintainer; source and licence still to be confirmed (see Next steps).
+ `userscript/Timeline-toolbar.js`: WikiEditor toolbar drop-down that inserts the four wikitext skeletons (install steps in the file header). Tested only against a mock of the WikiEditor API, not on a wiki.
+ `.github/workflows/pages.yml`: deploys `prototype/` to GitHub Pages on push to `main`.
+ `template/`: the paste-ready files, one per wiki page (`TimelineRail`, `TimelineRail__item`, `__event`, `__parallel`, `__gap`, `__section` edited by hand; `TimelineRail__styles.css`, `__doc` and `__testcases` generated by `python3 tools/build.py` from `prototype/timeline.css`, `tools/doc_source.wikitext` and the demo text in `tools/build.py`: never edit those three). `python3 tools/build.py --sandbox <User>` writes an untracked userspace copy to `sandbox/<User>/`.

## Behaviour

+ Design follows Vector: bold plain-text dates, Codex progressive blue dots, subtle grey rail, thumbnail-style image box.
+ 640 px and up: date column on the left, rail, then title, text and image.
+ Several events on one dot sit side by side and wrap (flex, 14 em minimum each).
+ Collapsible items, **on by default** for every item with content (`collapsible=no` opts out, `collapsed=yes` starts closed, `summary=` is the peek for multi-event items, `id=` overrides the generated id). The id is `{{anchorencode:date_title}}`, so two items with the same date and title on one page collide (use `id=`); anchorencode output with brackets (a wikilink as title) is untested as a class/id. The date row is a toggler (and carries the dot) for a `div.wt-timeline__body` holding the events and any nested timeline. Original description: the date row is a toggler (and carries the dot) for a `div.wt-timeline__body` holding the events and any nested timeline. It uses MediaWiki's own collapsible module via a *custom toggler* (`mw-customtoggle-ID` on the row, `mw-collapsible` + `id=mw-customcollapsible-ID` on the body), so the template ships no script, but the toggle needs JS in the reader's browser (without it the item stays open). Collapsed: hollow dot, date inline, title after a `|`. IDs must be unique per page and alphanumeric. `<details>`/`<summary>` was the first idea but English Wikipedia escapes them (checked through the parse API). Prototype: `collapsible-shim.js` emulates the module. Double-click on any dot (collapse/expand all of that timeline) cannot be done by a template, so it is the optional user script `userscript/Timeline-collapse-all.js` (also in the shim).
+ Pointer behaviour: the row is `pointer-events: none`; only the dot (`::before`) and the title/peek spans re-enable it and show the pointer cursor, so empty space on the row is inert. For a one-event item the title lives in the row (class `wt-timeline__peek--title`, an inline-block: bold line when open, after the date and a pipe when closed), so it is a toggler too; multi-event items toggle by dot only, and show the `summary` when closed. A section's title is a toggler. Section step-backs: the body has a page-coloured box-shadow so the outer rail does not show as a stub above the step.
+ Last item (`last=yes`, class `wt-timeline__item--last`): the line stops at that dot. The rail is one line for the whole list, so the item hides it below its dot with a page-coloured strip (`::after`); use it on the final item only. In grouped timelines the per-item rails simply stop.
+ Section connectors are rounded S-bends (radius 6px, 2px line) built from four small bordered boxes: A `row::after`, B `body::before`, C inner-list `::after`, D `body::after`; the rails stop where each curve starts (inner rail `top`/`bottom` offsets, body `box-shadow` that hides the outer rail down to the end of curve D). A nested section that is last in its list needs the extra 1em of body bottom padding so its bend and its parent's bend do not overlap.
+ Sections (`TimelineRail/section`, `li.wt-timeline__item--section`): a red dot (`--color-destructive`) and a bold title on the rail, plus a collapsible body (same `mw-collapsible` custom-toggler mechanism as items) holding an `ol.wt-timeline--section`, indented 1.5em. The body has the page background and is positioned so the outer rail does not run through the inner timeline. A section's list can contain sections, so nesting is unlimited (limited in practice by width and by MediaWiki's template expansion limits, untested). In groups and nested `sub` timelines the title uses the compact layout. Nesting of plain items alone is the older `sub` parameter.
+ Nested timelines: an `li` can hold an `ol.wt-timeline.wt-timeline--sub` after its events (template: `sub=` parameter of `TimelineRail/item`). It is indented under the parent's events, uses the compact layout (date above, rail on the left, lighter date) and can nest to any depth. Not tested inside grouped timelines.
+ Parallel timelines (`wt-timelines`): several separate timelines, each with its own dates, rail and optional heading, share a row and wrap when there is no horizontal space. They are independent and always use the compact layout (date above events), because the 640 px breakpoint follows the window, not the column.
+ Parallel and grouped (`wt-timelines--grouped`, window ≥ 640 px): the group is one flat grid (`display: contents` on the wrappers, 21 rows). Each heading sits in row 1 and starts a column, items flow down it, so the n-th item of every timeline shares a row and dots line up; `wt-timeline__item--gap` placeholders skip rows. Needs a heading per timeline, max 20 items, no trailing gaps. Columns share the width and do not wrap; under 640 px it falls back to the independent layout. First attempt used `@supports` + subgrid, which the TemplateStyles sanitizer rejects ("Invalid condition for @supports"), so it was removed.
+ Under 640 px: one column, rail on the left, date above the title.
+ Dark mode follows the Codex tokens (the prototype fakes them with `prefers-color-scheme`).

## Checked locally (headless Chrome, prototype only)

+ Wide (1100 px) and narrow (375 px), light and dark: layout holds, dot aligned with the date line.
+ Contrast: Codex blue dots on the base background are fine in both themes; the rail is decorative.
+ Screen readers: dots and rail are CSS only; the `<ol>` conveys order.
+ Wikilinks and templates in `title` and `text` work, since they are plain wikitext.
+ Not checked: real Vector 2022, the mobile skin, TemplateStyles sanitizer, any browser other than Chrome.

+ Collapsing mechanism (corrected): the `li` is the collapsible (`mw-collapsible`, `id=mw-customcollapsible-ID`, gets `mw-collapsed`), the row is the custom toggler (`mw-customtoggle-ID`, no state class is ever added to it), the body is `mw-collapsible-content`. `mediawiki.makeCollapsible.styles` sets `content: none !important` on `::before` of `.mw-collapsible[id^=mw-customcollapsible]`, so never use `::before` on the collapsible itself. Validate the stylesheet before pasting with the parse API (`contentmodel=sanitized-css`, `prop=parsewarningshtml`); `:has()` and `pointer-events` are rejected.

+ Double-click behaviour (user script `userscript/Timeline-collapse-all.js`, mirrored by the prototype shim): on an item's dot or date, collapse every collapsible item of that timeline, or expand them all if none is open; on a section's dot, keep that section open and close the other sections of its list, or open them all if they are all closed. An item without a title is collapsible too: `.wt-timeline__peek--title:empty` takes no room and shows no pipe, so a closed item shows only its date. Toggle ids must be plain and unique (they become a class name), so give such items an explicit `id=`.

+ MediaWiki's 2 MB post-expand include limit (measured with the parse API's `limitreporthtml` and `templatesandboxtitle`/`templatesandboxtext` to try template changes without saving them): every template level that receives content as a parameter counts that content again. A timeline is TimelineRail > section > item, so each item's text is counted about three times, plus the markup (about 1.1 KB of text and markup per item, 3x). Roughly 230 items with citations fit; the 546 items of "Timeline of historic inventions" do not (the article already uses about half the limit on its own). Findings: (a) checking `collapsible` three times in `item` is not what costs; the nesting is; (b) with the sections and the outer list written as plain HTML and only the items as templates, the whole article fits (about 1.9 MB), so a `section start`/`section end` pair of templates would be the way to support lists that long; (c) until then `tools/convert_inventions.py` converts only the headings named on its command line (default: Paleolithic and Agricultural and proto-agricultural eras, 228 bullets, about 1.9 MB with collapsible items) and leaves the rest of the article as it is.
