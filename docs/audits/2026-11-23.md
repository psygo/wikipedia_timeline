# Audit 2026-11-23 (first audit, commits 1 to 129)

Scope: everything tracked except generated drafts. Tag `audit-last` set at the commit that adds this report.

## Security

| Severity | Where | Finding | Status |
| --- | --- | --- | --- |
| Low | `prototype/collapsible-shim.js` (message listener) | Accepted `wtGoto` messages from any window. Impact: another page framing the prototype could change its URL hash and open items. No data is read or leaked. | Fixed: only messages from `window.parent` are accepted. |
| Low | `prototype/collapsible-shim.js` (`postMessage(..., '*')`) | Sends only the URL hash to the parent, with no target origin. Nothing sensitive, and the prototype is public. | Left as is (the parent origin is not known in the viewer). |
| Low | `.github/workflows/pages.yml` | Actions pinned to major tags (`@v4`, `@v5`, `@v3`), not commit SHAs. Permissions are already minimal (`contents: read`, `pages`, `id-token`). | Open: pin to SHAs if wanted. |
| Info | `lua/*.lua` | Everything interpolated into HTML goes through `esc` or `anchor`, or is a number from `tonumber` (box widths, indents). Free text is returned as wikitext, so MediaWiki's sanitizer applies. No `style`, `href` or `src` is built from arguments. | OK |
| Info | CSS (`template/TimelineRail__styles.css`) | No `url()`, `@import`, `expression`, `behavior` or `position: fixed`. | OK |
| Info | Userscripts, prototype, web component, React | No `innerHTML`, `eval`, `new Function`, `document.write` or `dangerouslySetInnerHTML`. `localStorage` is used only for the theme. | OK |
| Info | Dependencies | `react/`: `npm audit --omit=dev` reports 0 vulnerabilities. `web-component/` has no dependencies (and no lockfile, so `npm audit` does not apply). | OK |
| Info | Secrets | No tokens, keys or credentials in the tracked files or in the last 200 commits (pattern scan). `tools/.cache/` is git-ignored. | OK |
| Low | `tools/*.py` | `curl` calls had no timeout, so a stalled request could hang a converter. Calls go only to en.wikipedia.org and the sources named in each converter, and no shell is used. | Fixed: `--max-time 60` on every call. |

## Efficiency

Measured with the live parse API (`prop=limitreportdata`).

| Draft | Post-expand include size | Parser CPU | Lua time | Lua memory | Expensive functions |
| --- | --- | --- | --- | --- | --- |
| Timeline of mathematics | 853,066 of 2,097,152 (41%) | 1.35 s | 0.41 s | 17.0 MB | 3 |
| Timeline of Go | 386,900 of 2,097,152 (18%) | 1.40 s | 0.50 s | 17.2 MB | 2 |

- No draft is near the 70% threshold. The mathematics draft is the largest; room remains for about 140 more events of the same size.
- The Lua modules make no `frame:preprocess`, `mw.title`, `#ifexist` or `expandTemplate` calls. All pages are built with plain string concatenation.
- `convert_math.py` fetches through a cache (`tools/.cache/math_info.json`), and rerunning it makes no new requests.
- Not measured: size of the generated HTML per event, and unused CSS rules. Both are worth a look in the next audit.
