# Module:TimelineRail (Lua)

The same timeline as the `template/` family, generated by a Scribunto module instead of nested
templates with parser functions. It writes the same markup and uses the same stylesheet
(`Template:TimelineRail/styles.css`, i.e. `prototype/timeline.css`), so the result looks and behaves the same:
the output of `item` and `section` was compared with the live template's expansion and is identical
(apart from `&#32;` entities the template needs for spaces).

```
lua/
  Module_TimelineRail.lua            paste into Module:TimelineRail
  Module_TimelineRail__doc.wikitext  paste into Module:TimelineRail/doc
  template/                          thin wrappers: {{#invoke:TimelineRail|…}}, same names as template/
  test/test.lua, test/mw_mock.lua    local tests (no wiki needed)
```

## Why a module

* **Size.** The templates pass each item's text through `item` → `section` → `TimelineRail`, and the post-expand
  include size counts it at every level (about 3× the text, which is why the whole *Timeline of historic inventions*
  does not fit). `{{TimelineRail/outline|text=…}}` takes the whole timeline once and builds it once.
  Measured on the live parser: see the table below.
* **Readability.** The markup is built in one place, in Lua, instead of `#if` chains with `&#32;` workarounds.
* **Table of contents.** `outline` makes the title of each section a real `<h3>` heading (nested sections one level deeper), so the page's table of contents lists them. `|toclevel=2` to `6` sets the top level (default 3); `|toc=no` gives plain titles again. Needs the new `Module:TimelineRail` and the new `Template:TimelineRail/styles.css` (the heading reset); the switcher and the List and Table modules are unchanged.
* **Testing.** `luajit lua/test/test.lua` runs 50+ checks locally (HTML shape, balanced tags, unique ids, outline parsing).

## Entry points

`rail`, `parallel`, `item`, `section`, `event`, `gap` take the same parameters as the templates with those names.
`outline` is new: a bulleted/heading text becomes the timeline. See `Module_TimelineRail__doc.wikitext`.

```wikitext
{{TimelineRail/outline
|text=
== Lower Paleolithic ==
* '''3.3 mya''' Oldest known stone tools.
* 400 kya ;; Fire ;; Controlled use of fire.
}}
```

Readers without the script (everyone on the mobile site, anyone with JavaScript off, until the gadget exists) see only the **default
view**, which is the first one unless a `*` marks another (`*Timeline=...`, or `\|default=List`). So the original text is never lost, but
those readers cannot reach it unless it is the default. Footnotes are kept in the default view only (see below).

## Switching views: separate modules

`Module:TimelineRail` only draws timelines. Showing the same data as a list or a table, and the **View**
button that switches between them, are other components. Each works alone.

| Module | What it does | Paste from |
|---|---|---|
| `Module:ViewSwitcher` | `{{#invoke:ViewSwitcher\|switch ...}}`: wraps several views, each any wikitext or the output of any module function, in one box | `lua/Module_ViewSwitcher.lua` |
| `Module:ViewSwitcher/styles.css` | the button and menu (passes the TemplateStyles sanitizer) | `lua/ViewSwitcher__styles.css` |
| the button itself | the script that builds the dropdown (MediaWiki:Gadget-ViewSwitcher.js, or User:Fanaro009/ViewSwitcher.js loaded from your common.js to try it) | `userscript/ViewSwitcher.js` |
| `Module:OutlineList` (optional) | `{{#invoke:OutlineList\|list \|text=...}}`: the outline as a plain bulleted list | `lua/Module_OutlineList.lua` |
| `Module:OutlineTable` (optional) | `{{#invoke:OutlineTable\|table \|text=...}}`: the outline as a `wikitable` | `lua/Module_OutlineTable.lua` |

**The list and table modules are optional.** They add no styling: they write a plain `<ul>` and a
`class="wikitable"`, the default Wikipedia elements. All they do is write them from the same outline, so the
data is typed once and the three views cannot drift apart. Without them, give the switcher views you wrote
yourself (`|label2=List |view2=* ...`, `|label3=Table |view3={| class="wikitable" ...`); that repeats the data
in the page source.

```
{{#invoke:ViewSwitcher|switch
|views=Timeline=TimelineRail.outline; List=OutlineList.list; Table=OutlineTable.table
|id=inv1
|text=
== 3.3 Mya - 1 Mya ==
* '''3.3 Mya''' Stone tools ...
}}
```

`Label=Module.function` pairs; every other argument goes to every function. Views you write yourself:
`|label1=Photos |view1=... |label2=Map |view2=...`, and `|default=2` picks the view shown first.
Without the script the reader sees the first view only. The list and table read the outline with
`Module:TimelineRail`'s `parseOutline`. In sandboxes, name every module `.../sandbox` and add
`|parser=TimelineRail/sandbox` (the converters do). The converters write this call with `--switcher` (or
`--switcher=ViewSwitcher/sandbox`); the Earth draft is
`drafts/Timeline_of_first_images_of_Earth_from_space__lua_views.wikitext`.

Wikipedia already has `{{Switcher}}` (Module:Switcher plus the default-on `Gadget-switcher.js`, radio
buttons); it is made for swapping images in infoboxes, so this is a separate, dropdown-style module.
Each view is written out in the page, so mind the post-expand size: the Earth outline in three views is
about 175 kB; the 543-item inventions article in three views would likely pass the 2 MB limit and need splitting.

Tests: `luajit lua/test/test_switcher.lua`.

(the default), and the article's own text as one of them, as it is (a list for the inventions, a table for Earth and AI); the
other two are made from the outline. Add `--module=TimelineRail --switcher` for the live module names. Checked against the live articles:

Footnotes: the same `<ref>` in three views would be listed three times, so `Module:ViewSwitcher` removes the reference markers
from every view but the default (`|refs=all` keeps them). That works on the markers MediaWiki hands modules in place of `<ref>`;
it is untested on a wiki.

### Timeline only, measured on the wiki

| Draft | Post-expand include size (limit 2,097,152) | Content check |
|---|---|---|
| Earth, templates | 504,268 | |
| Earth, outline | 316,376 | all 82 rows (sections, dates, text, pictures) equal to the template version |
| Inventions, templates, 231 items | 1,882,259 | |
| Inventions, outline, 543 items | 1,448,598 | all 543 bullets equal to the original article's |

Scribunto does not keep module state between `#invoke` calls, so the generated ids cannot come from a counter: they come from
`|id=` if given, otherwise from a hash of the outline's text (two different outlines never share a prefix). With an old module
that repeated ids, MediaWiki cannot match togglers to their items and shows a `[hide]` link on each item instead of using the dot.

## Limits

* Not run on a wiki yet; the local tests use a small mock of the `mw` library (`test/mw_mock.lua`).
* `outline` is a new syntax: it has to be accepted by editors, and a literal `|` in the text must be written `{{!}}`.
* Item `id`s generated by `outline` are `tl<n>_i<m>`, unique within the page, but they change if outlines are added above.
* The module returns `[[File:…]]` and `<ref>` markup as wikitext; MediaWiki processes it after the module returns, as for any template.
